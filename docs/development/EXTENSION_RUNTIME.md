# Read-only extension runtime candidate

This candidate adds an opt-in stdio runtime bundle to support multi-file language-runtime MCP servers, not provider-specific adapters. The operator stages trusted files below the configuration directory at `upstream-bundles/<id>` and registers the provider with `veyl mcp-servers add-bundle ID /absolute/COMMAND [ARGS...]` (use the normal explicit configuration selector when appropriate). The JSON provider flag is `runtime_bundle: true`. The sandbox mounts only that bundle at `/upstream/bundle`, read-only, using a validated pinned directory descriptor. Use private 0700 directories and 0600 regular files; symbolic links, hardlinks, special objects, mount crossings and over-limit trees are rejected. The existing executable and single-file Python paths remain available. No host home, credentials, writable project mount, network access or automatic package installation is granted by this feature. Existing exact per-client tool grants remain required. The bundle flag is included in provider configuration fingerprints; those fingerprints are not content hashes of packages. Install and update packages only from operator-reviewed sources. The provider is started afresh for each discovery or call; stateful and long-lived sessions are not implemented here. Qualified bundled calls receive at most four seconds inside the existing five-second HTTP envelope; ordinary provider and discovery deadlines are unchanged.

## Verification

The independently written multi-module Node fixture (`tests/runtime_bundles.py`) passed invocation and exact-grant, cross-client, read-only mount and sibling isolation checks, plus hardlink/symlink rejection. REA 6.10.1 artifact family (27 tools) and Rust Anything v4.1.0 (22 tools) discovered through real MCP. Rust Anything analyzed a two-line Python fixture. REA invocation with the original 1.7-second link deadline timed out for both SQLite and Python bytecode probes. With the scoped four-second deadline, REA `inspect_python_pyc` succeeded, returning observed structured evidence with the expected `veyl_extension_canary` code object. Both real-provider calls and negative ungranted-tool/cross-client checks passed (`REAL_PROVIDER_CALLS_PASS`, process `mwvxe6w3-h05cve`, exit 0). SQLite was not retested at the new deadline. Full arbitrary third-party package compatibility is not established.

An offline RustSec check evaluated 86 locked registry package versions against local advisory database revision `55e1c3dfbd834237a05bbbf7b50ba3b5be27b662` (2026-11-21), using cached official Rust semver 1.0.28. No applicable advisories matched (47 non-withdrawn matching-package advisory evaluations). This is not a fresh online cargo-audit run; cargo-audit is unavailable and its cached source requires an uncached dependency. Registry-yank checking and newer advisories are not covered.

Original parity-86 candidate and release binaries remain unchanged. No production configuration, grants, deployment or service restart. See sibling `bundled-provider-probe.py` and `audit-rustsec.py` for the disposable provider and advisory checks.
